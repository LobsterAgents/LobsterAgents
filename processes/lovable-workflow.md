# Lovable.dev Workflow

## Overview

Lovable.dev is used for rapid prototyping and first versions. **Credits cost money** — don't waste them building the wrong thing.

## Process

### 1. Start in Plan Mode

Before typing your prompt:
- Click **"Plan"** toggle in the chat input area
- This tells Lovable to ask clarifying questions first
- Do NOT immediately ask it to build

### 2. Let Lovable Ask Questions

Lovable will ask questions to understand:
- Scope and features
- Design preferences
- Technical requirements
- Edge cases

**For each question:**
1. Check if Marc is available
2. If yes → get Marc's input
3. If no → make a recommendation based on requirements
4. Always note when you're making assumptions

### 3. Build After Clarification

Only tell Lovable to build when:
- All questions are answered
- Requirements are clear
- Marc has approved (if available)

### 4. Watch for Follow-up Questions

After building, Lovable may ask:
- "What's next?"
- Suggestions for improvements
- Clarifying questions about behavior

**Pay attention to these!** They often catch edge cases.

### 5. Review Before Publishing

Before clicking Publish:
- Test the preview
- Verify it matches requirements
- Get Marc's approval if significant

## Key Principles

| Principle | Why |
|-----------|-----|
| Plan before build | Avoids wasted credits |
| Ask Marc when available | His input = priority |
| Make recommendations | Keep things moving when Marc is busy |
| Don't rush | Getting it right > getting it fast |

## Credit Conservation

- Each build attempt uses credits
- Wrong builds = wasted credits
- Clarification is free, rebuilding is not

## When to Check with Marc

- Scope decisions
- Design direction
- Feature prioritization
- Anything ambiguous
- Before publishing

## When to Make Recommendations

- Marc is unavailable
- Question is minor/technical
- Clear best practice exists
- Time-sensitive and low-risk

Always note: "I recommended X because Y — let me know if you'd prefer something different."
